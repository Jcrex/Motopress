¿(10×8) + (8×1)?

Broadcasting: reglas

1Se alinean las formas por la derecha.

2Cada par de dimensiones debe ser igual, o una de las dos debe valer 1 (y se estira).

3Si a una forma le faltan dimensiones por la izquierda, se rellenan con 1: (8,) → (1, 8).

respuesta(10, 8) + (8, 1) no se puede: la última pareja vale (8 con 1), pero la primera es 10 frente a 8. Con (1, 8) o con (8,) sí.
Las formas se escriben una debajo de otra, alineadas por la derecha, y se comparan pareja a pareja. Una pareja es compatible si los dos números son iguales o si uno vale 1: el 1 se «estira» copiando los datos virtualmente. Con (10,8) y (8,1): la pareja de la derecha es 8 y 1, compatible; la de la izquierda es 10 y 8, incompatible. NumPy lanza ValueError. Con (1,8) ambas parejas son compatibles y el resultado es (10,8).

En cambio (8,) se interpreta como (1,8), y (10,1) es una columna que se copia a lo largo de las 8 columnas. Ojo con (10,): se alinea por la derecha con el 8 y falla. El ejemplo de la derecha es el «producto exterior»: una columna más una fila da una matriz completa sin bucles. El precio del broadcasting es algo de memoria temporal; el beneficio, evitar bucles.

def brighten_loop(im, p=2):         # ✗ bucles
    out = np.zeros(im.shape)
    for i in range(im.shape[0]):

def darkenImg(im, p=2):
    return (im ** float(p)) / (255 ** (p - 1))
$$T(r)=255\left(\tfrac{r}{255}\right)^{p}$$r en [0,1], potencia, reescalado
$$=255\,\frac{r^{p}}{255^{p}}$$(a/b)ᵖ = aᵖ/bᵖ
$$=\frac{r^{p}}{255^{\,p-1}}$$255/255ᵖ = 255¹⁻ᵖ
float(p)Con p entero, uint8 ** 2 sigue en uint8 y desborda.
Como 0 ≤ r/255 ≤ 1, elevar a p > 1 achica los valores: la imagen se oscurece, y más cuanto mayor es p. Los extremos no cambian: T(0)=0 y T(255)=255. Ejemplo con p = 2 y r = 100: 100² / 255 = 39,2. Por qué float(p): si p es un entero y la imagen es uint8, im ** 2 se calcula en uint8 y desborda antes de dividir. En 255 ** (p-1) no hay problema porque 255 es un entero de Python, que no desborda.

def brightenImg(im, p=2):

Con exponente 1/p < 1 los valores normalizados suben: la imagen se aclara. np.power es la versión vectorizada de x ** y: trabaja elemento a elemento sobre todo el array y admite broadcasting. math.pow es solo para escalares. Aquí 255.0 ** (p-1) es un float, así que el producto con la imagen ya sale en float64 y no hay desbordamiento.

ecualización del histograma

histeq, línea a línea

def histeq(im, nbins=256):
    imhist, bins = np.histogram(im.flatten(), list(range(nbins)))
    cdf = imhist.cumsum()               # histograma acumulado
    factor = 255 / cdf[-1]              # cdf[-1] = nº de píxeles
    im2 = np.interp(im.flatten(), bins[:-1], factor * cdf)
    return im2.reshape(im.shape), cdf
LíneaQué obtiene
np.histogramh(l): nº de píxeles con nivel l
cumsumcdf(l): píxeles con nivel ≤ l
factor * cdfT(l), ya en [0, 255]
np.interpT evaluada en cada píxel
reshapevuelve a (H, W)
$$T(l)=255\,\frac{\mathrm{cdf}(l)}{N}$$

factor * cdf es la T(l) escalada a [0, 255]; np.interp la evalúa en cada píxel.

ideaLos niveles se reparten según la probabilidad acumulada: los más frecuentes se «separan» más.
Línea por línea. Uno: np.histogram cuenta cuántos píxeles hay en cada nivel. Dos: cumsum acumula esos conteos, de modo que cdf[l] es el número de píxeles con nivel menor o igual que l. Tres: el último valor de cdf es el número total de píxeles N. Cuatro: factor multiplicado por cdf vale 255 por la CDF normalizada, que es la función de transformación T. Cinco: np.interp evalúa esa tabla en el nivel de cada píxel. Seis: reshape devuelve la forma original porque trabajamos con la imagen aplanada. Recuerda la errata: la ecualización no aumenta la entropía, la deja igual o la reduce un poco.

np.histogram devuelve dos arrays: los conteos y los bordes de las cajas; los bordes tienen un elemento más que los conteos. Si bins es un entero, son cajas iguales entre el mínimo y el máximo de los datos; si es una lista, son los bordes. Todas las cajas son semiabiertas [a,b) salvo la última, que es cerrada [a,b]. Con 256 bordes de 0 a 255 hay 255 cajas, y los niveles 254 y 255 se cuentan juntos. Es una pequeña imprecisión del código del profesor: lo correcto sería bins=np.arange(257), con 256 cajas. Por eso en la ecualización los niveles 254 y 255 acaban con el mismo valor de salida, 255.

np.interp hace interpolación lineal por tramos: dada la tabla (xp, fp), une los puntos con segmentos rectos y evalúa en x. def checkBoardImg(im, m, n):        # m × n celdas
    i, j = np.indices(im.shape[:2]) # fila, columna
    ci = i * m // im.shape[0]       # celda 0…m−1
    cj = j * n // im.shape[1]       # celda 0…n−1
    inv = (ci + cj) % 2 == 1        # alternas
    return np.where(inv, 255 - im, im)
$$\text{invertir si }(c_i + c_j)\bmod 2 = 1$$

Celdas vecinas difieren en 1 en ci o en cj: su suma cambia de paridad. Es el patrón del ajedrez.

(ci + cj) mod 2 para m = n = 4: 1 = celda invertida

Cada píxel (i, j) pertenece a la celda (i·m // alto, j·n // ancho). Con alto 663 y m = 4, la fila 165 está en la celda 0 y la 166 en la 1: la división entera reparte bien aunque 663 no sea múltiplo de 4. La versión con alto de celda ch = alto // m daría un resto sin cubrir. Se invierte la celda si la suma de índices es impar. np.where(cond, x, y) elige x donde cond es verdadera e y donde es falsa, sin bucles.

E5 · cuántos histogramas

$$\text{nivel } l:\; 2^l\times 2^l = 4^l$$cada nivel parte cada bloque en 4
$$N(n)=\sum_{l=0}^{n-1}4^l$$niveles 0 … n−1
$$=\frac{4^{n}-1}{4-1}=\frac{4^n-1}{3}$$serie geométrica: Σrˡ = (rⁿ−1)/(r−1)

prueba rápidaSi S = 1 + r + … + rⁿ⁻¹, entonces rS − S = rⁿ − 1, y de ahí S = (rⁿ − 1)/(r − 1).
El nivel 0 es la imagen completa: 1 histograma. El nivel 1 son los cuatro cuadrantes: 4. El nivel 2, dieciséis bloques. En total, la suma de una serie geométrica de razón 4: (4^n − 1)/3. def multiHist(im, n, bins=256):
    hists = []
    for l in range(n):          # 4^l bloques
        k = 2 ** l
        rs = np.linspace(0, im.shape[0], k + 1).astype(int)
        cs = np.linspace(0, im.shape[1], k + 1).astype(int)
        for i in range(k):
            for j in range(k):

    return hists

ejercicio 6 · transformación exponencial

E6 · expTransf

$$T(l_0)=l_0,\quad T(l_1)=l_1$$el rango no cambia
$$a\,(g_1-g_0)=l_1-l_0$$restar; g = e^(−αl²)
$$a=\frac{l_1-l_0}{g_1-g_0}$$α > 0 ⇒ g decrece ⇒ a < 0
$$b=l_0-a\,g_0$$de T(l₀) = l₀
def expTransf(alpha, n, l0, l1, bInc=True):
    l = np.linspace(l0, l1, n)
    g = np.exp(-alpha * l**2)
    a = (l1 - l0) / (g[-1] - g[0])
    b = l0 - a * g[0]
    T = a * g + b            # creciente
    return T if bInc else T[::-1]
Comprobado contra el PDF: la potencia es l al cuadrado, T(l) = a e^{-α l²} + b. Imponemos T(l0) = l0 y T(l1) = l1. Restando las dos ecuaciones sale a por la diferencia g1 menos g0 igual a l1 menos l0; despejamos a y después b. Como α > 0, g es decreciente, así que a es negativa y T resulta creciente. Para la versión decreciente basta dar la vuelta al array: T[::-1]. np.linspace(a, b, n) genera n valores igualmente espaciados incluyendo ambos extremos.
