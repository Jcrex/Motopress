¿Qué función llamo?

Cada píxel depende solo de sí mismo→aritmética NumPy: a*im**g, np.where, LUT T[im], np.clip
Suma ponderada de una ventana (lineal)→convolve(im, mask) · gaussian_filter(im, sigma)
Contar o sumar en una ventana→umbral booleano, luego convolve(·, np.ones((sX,sY)))
Ordenar la ventana (mediana, mín., máx.)→medfilt2d · median_filter · minimum_filter · maximum_filter
Filtro grande o definido por frecuencias→np.fft.fft2 + máscara + ifft2
Bordes · rectas→sobel, feature.canny · hough_line
Mezclar dos imágenes según una máscara→combinación convexa a*im1 + (1-a)*im2
Esta diapositiva es la que hay que memorizar. Cada fila es una operación de teoría: punto (lección 1), vecindad lineal (lección 2), vecindad no lineal (lección 2), frecuencia (lección 3), bordes (lección 4) y rectas (lección 5, lab 4).

ejercicio 1 · teoría

Qué hace la máscara

(a) Detector de líneas a +45° (T4). Los 2 están en la diagonal «/».

$$\sum_{i,j} h(i,j) = -1-1+2-1+2-1+2-1-1 = 0$$

Suma 0 ⇒ en una zona plana la respuesta es 0: no detecta el nivel de gris, solo el cambio.

(b) Simetría central: girada 180° queda igual ⇒ convolve y correlate dan lo mismo (T2).

h

h girada 180°

$$h(i,j)=h(-i,-j)\;\Rightarrow\; f*h=f\star h$$
Girar 180° es invertir filas y columnas a la vez. La fila de arriba [-1,-1,2] pasa abajo invertida [2,-1,-1], y la de abajo pasa arriba invertida: el resultado es la misma matriz. Por eso conv y corr coinciden. Una máscara de Sobel, en cambio, es antisimétrica: al girarla cambia de signo.

ejercicio 2 · solución

Por qué funciona

def countIm(im, thr, sX, sY, minCount):
    im_th = (im < thr).astype(float)
    return convolve(im_th, np.ones((sX, sY))) >= minCount
$$c(i,j)=\sum_{(u,v)\in W} 1\cdot b(i+u,\,j+v)=\#\{\text{píxeles con }f\lt thr\}$$

Los pesos son 1, así que cada píxel de la ventana suma su valor: 0 si no cumple, 1 si cumple. La suma cuenta.

trucoEl núcleo de unos es simétrico: conv = corr, no importa el giro.
en el examenVariantes: «porcentaje» ⇒ dividir por sX*sY (uniform_filter); «media local» ⇒ lo mismo con la imagen sin umbral.
La solución son dos líneas. El astype(float) es necesario porque convolve con un array booleano daría un resultado booleano o un error de tipo, según la versión. La comparación final con minCount devuelve una máscara booleana del mismo tamaño que la imagen.

ejercicio 2 · detalles

Filas, bordes y bucles

¿sX son filas o columnas? np.ones((sX, sY)) tiene sX filas y sY columnas.

Bordes: mode='reflect' (por defecto) cuenta píxeles reflejados; mode='constant' trata el exterior como 0.

realEn cat256 con 3×3, thr=60 y minCount=4, los dos modos difieren en 19 de 65 536 píxeles, todos en el borde.
def countIm(im, thr, sX, sY, minCount):
    out = np.zeros(im.shape, bool)
    for i in range(im.shape[0]):
        for j in range(im.shape[1]):
            w = im[max(0,i-sX//2):i+sX//2+1,
                   max(0,j-sY//2):j+sY//2+1]
            out[i,j] = (w < thr).sum() >= minCount
    return out
La versión con bucles equivale a mode='constant' y es válida, pero lenta (Python puro, un píxel cada vez) y más larga. En el examen se acepta, pero la vectorizada es la que se espera.

ejercicio 3 · combinación convexa

Combinación convexa

def blurFgBk(im, fgMask, bFg, sigma):
    im_f = gaussian_filter(im, sigma)
    if bFg:
        a, b = 1 - fgMask, fgMask
    else:
        a, b = fgMask, 1 - fgMask
    return a*im + b*im_f
def blurFgBk(im, fgMask, bFg, sigma):
    im_f = gaussian_filter(im, sigma)
    return np.where(fgMask == bFg, im_f, im)
$$out = a\cdot im + b\cdot im_f,\quad a+b=1$$

Por píxel, \(a,b\in\{0,1\}\): se elige im o im_f. Con bFg=True, \(b=\)máscara: el objeto sale borroso.

comprobadoAmbas versiones dan el mismo resultado (np.allclose) para bFg=True y False.
Una combinación convexa mezcla dos imágenes con pesos que suman 1. Con una máscara binaria, a y b son 0 o 1, así que en cada píxel solo queda una de las dos. Con una máscara suave (valores entre 0 y 1) se obtendría una transición gradual, que es lo que se hace en blending. np.where es la forma más corta, pero la combinación convexa generaliza.

ejercicio 4 · realce puntual (T1)

Corrección gamma

$$s = a\cdot r^{\gamma}$$

Con \(\gamma = 1/2.2\) y \(r\in[0,1]\): \(0{,}5\mapsto 0{,}73\), \(0{,}25\mapsto 0{,}53\). Aclara.

\(\gamma>1\) oscurece. Solo vale en [0, 1]: si la imagen está en [0, 255], primero divide entre 255.

Una curva por encima de la diagonal aclara; por debajo, oscurece. Con gamma menor que 1 se amplían los grises oscuros, de ahí que sea la corrección típica de pantalla. Valores calculados: 0.5 elevado a 1/2.2 es 0.7297 y 0.25 elevado a 1/2.2 es 0.5325.

ejercicio 4 · solución

gamma y rgb2gray

def gamma_correction(im, a, gamma):
    return a * im**gamma

def rgb2gray(im_rgb):
    coeffs = np.array([0.2126, 0.7512, 0.0722])
    gamma = 1 / 2.2
    # opción 1: corregir y luego ponderar
    im_g = gamma_correction(im_rgb, 1, gamma)
    return (coeffs[0]*im_g[:,:,0]
          + coeffs[1]*im_g[:,:,1]
          + coeffs[2]*im_g[:,:,2])
    # opción 2: el peso va en el parámetro a
    R, G, B = (im_rgb[:,:,k] for k in range(3))
    return (gamma_correction(R, coeffs[0], gamma)
          + gamma_correction(G, coeffs[1], gamma)
          + gamma_correction(B, coeffs[2], gamma))
El enunciado da los coeficientes y la gamma. La opción 1 aplica gamma con a = 1 a los tres canales a la vez y después pondera. La opción 2 llama a gamma_correction canal por canal usando a como peso. Ejecutadas ambas sobre peppers: np.allclose da True.

ejercicio 5a · solución explicada

5a línea a línea

def add_TLA_noise(im, p=0.1):
    im = im.copy()
    t, l, a = 1, 2, 3
    pattern = {t:[1,0,0], l:[0,1,0], a:[0.5,0,0.5]}
    m, n, k = im.shape
    where = np.random.rand(m, n) < p
    which = np.random.randint(t, a+1, (m, n))
    which_where = which * where
    for nt in [t, l, a]:
        im[which_where == nt, :] = pattern[nt]
    return im
where(m,n) bool: píxel afectado, con probabilidad p
which(m,n) en {1,2,3}: tipo, uniforme ⇒ p/3 cada uno
which*where0 si no afectado; si no, su tipo
im[mask,:]máscara 2D elige filas (N,3); el vector RGB se propaga
Truco central: multiplicar el tipo por la máscara booleana deja un 0 donde no hay ruido y el número del tipo donde sí. Indexar con una máscara 2D sobre una imagen (m,n,3) selecciona los píxeles completos, y asignar un vector de longitud 3 se propaga por broadcasting a los tres canales. Por eso no hacen falta flatten ni reshape. Ojo: randint excluye el extremo superior, de ahí el a+1.

ejercicio 5b · justificación

5b: la mediana

def remove_TLA_noise(im_noisy):
    im = np.copy(im_noisy)
    for k in range(im.shape[2]):
        im[:, :, k] = medfilt2d(im_noisy[:, :, k])
    return im

T y L son, por canal, ruido impulsivo: sal en un canal y pimienta en los otros. La mediana lo elimina.

A (valor ½) no es extremo, pero la mediana quita los valores poco representativos de la vecindad, aunque no sean extremos.

¿por qué no la media? Un impulso se reparte entre los vecinos: extiende el ruido en vez de quitarlo (T2, lab 2).
Es la respuesta del profesor, parafraseada. Se aplica por canal porque el ruido es de color pero cada canal por separado se comporta como sal y pimienta. Una alternativa robusta, fuera del alcance del ejercicio, sería convertir los valores intermedios a extremos antes de filtrar.

$$f*h=\mathcal F^{-1}\{F\cdot H\}$$1. convolución = producto en frecuencia
$$O(MN\log MN)+O(MN)$$2. FFT y producto
$$O(MN\,mn)$$3. coste espacial: crece con el núcleo
Razonamiento en tres pasos. Uno: el teorema dice que la transformada de la convolución es el producto de transformadas. Dos: la FFT cuesta M N log M N y el producto, M N. Tres: filtrar directamente cuesta M N por m n, que crece con el tamaño del núcleo. Si el núcleo es grande, la frecuencia gana.

justificación completa

Matices del coste

$$m^2\ \text{vs}\ 2\log_2(MN)=2\cdot18\Rightarrow m\approx 6$$

Solo con núcleos grandes: hasta m = 6 gana el espacial; desde m = 7, la FFT. Un núcleo separable (2m) no cede hasta m = 18.

Solo filtros lineales e invariantes: la mediana no es lineal.

DFT = convolución circular: hay que rellenar (padding) para igualar la lineal.

Comparamos M N m n frente a 2 M N log2(M N), la cuenta de la diapositiva 17 de la lección 3. Para 512 por 512, log2 de M N es 18, así que 2 por 18 es 36 y m al cuadrado igual a 36 da m = 6. Comprobado también que fftconvolve y convolve coinciden, y que la DFT directa difiere de la lineal en el borde.

lowpassFreq

ejercicio de práctica

Escribe lowpassFreq(im, r): paso bajo ideal de radio r en el dominio de la frecuencia.

pistafft2, fftshift, meshgrid para el círculo, y deshacer en orden inverso.
def lowpassFreq(im, r):
    m, n = im.shape
    F = np.fft.fftshift(np.fft.fft2(im))
    y, x = np.meshgrid(np.arange(m) - m//2,
                       np.arange(n) - n//2, indexing='ij')
    H = (x**2 + y**2) <= r**2
    return np.fft.ifft2(np.fft.ifftshift(F*H)).real
Comprobado: con r enorme devuelve la imagen original y con r = 30 conserva la media. Se toma la parte real porque la imaginaria es ruido numérico (la máscara es simétrica). El borde brusco del círculo causa ringing: pruébalo con una gaussiana.

edgeMap

ejercicio de práctica

Escribe edgeMap(im, sigma, t): suaviza, calcula Sobel en x e y, la magnitud y umbraliza con un umbral relativo t.

pistaRelativo = fracción del máximo de la magnitud.
def edgeMap(im, sigma, t):
    s = gaussian_filter(im.astype(float), sigma)
    gx = sobel(s, axis=1)
    gy = sobel(s, axis=0)
    mag = np.hypot(gx, gy)
    return mag > t * mag.max()
Se suaviza antes porque la derivada amplifica el ruido. En scipy, axis=1 deriva en horizontal (gx) y axis=0 en vertical (gy). La magnitud hypot es isótropa, al contrario que la suma de valores absolutos. Un umbral relativo se adapta al contraste de cada imagen.

Escribe histEq(im) en 3 líneas para una imagen uint8.

pistaHistograma, CDF escalada a [0, 255] y tabla de consulta (LUT).
def histEq(im):
    h = np.bincount(im.ravel(), minlength=256)
    T = np.round(255*np.cumsum(h)/im.size).astype(np.uint8)
    return T[im]
T[im] indexa la tabla con la propia imagen: cada píxel se sustituye por T de su nivel. La entropía no sube, baja un poco: es la errata de los apuntes que hay que corregir. Resultado ejecutado con iglesia.pgm.
